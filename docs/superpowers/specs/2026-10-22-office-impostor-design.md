## 게임 규칙

### 인원과 역할
- 4~10명. 방장이 대기실에서 임포스터 수를 1 또는 2로 고른다. 기본 1. 7명 이상일 때만 2를 고를 수 있다.
- 색 10개 (빨강·파랑·초록·분홍·주황·노랑·검정·흰색·보라·청록). 입장 순서대로 빈 색을 받고, 대기실에서 바꿀 수 있다.
- 시작하면 무작위로 임포스터를 뽑는다. 나머지는 직원.

### 조작
- 이동: WASD 또는 방향키
- 사용(임무·환풍구·버튼): E 또는 스페이스
- 킬: Q (임포스터만)
- 신고: R (시체 근처에서만)
- 사보타주 메뉴: Tab (임포스터만)
- 미니게임과 회의는 마우스

### 맵: 사무실 한 층
방 8개와 복도. 각 방에 있는 것:

| 방 | 임무 장소 | 기타 |
|---|---|---|
| 회의실 | 결재 도장 찍기 | 긴급 회의 버튼 (가운데 탁자) |
| 탕비실 | 커피 내리기 | 환풍구 A1 |
| 서버실 | 서버 케이블 색 맞추기 | 서버 과열 복구 패널 1 |
| 렌더팜 | 렌더 큐 걸기 | 서버 과열 복구 패널 2, 환풍구 B1 |
| 복사실 | 복사기 용지 넣기 | 환풍구 A2 |
| 휴게실 | 화분 물 주기 | 환풍구 C1 |
| 대표실 | 결재 도장 찍기 | 환풍구 B2 |
| 창고 | 복사기 용지 넣기 | 두꺼비집(정전 복구), 환풍구 C2 |

- 맵은 칸(32px) 격자로 정의한다. 벽은 직사각형 목록이다.
- 시작 위치는 회의실 탁자 둘레.

### 임무
- 미니게임 6종. 마우스로 하고 10초 안팎이면 끝난다.
  1. **복사기 용지 넣기**: 종이 묶음을 끌어서 용지함에 넣는다.
  2. **렌더 큐 걸기**: 목록에서 샷 3개를 순서대로 체크하고 "렌더" 버튼을 누른다. 진행 바가 찬다.
  3. **커피 내리기**: 버튼을 누르고 있다가 잔이 선까지 찼을 때 뗀다. 넘치면 다시.
  4. **서버 케이블 색 맞추기**: 왼쪽 4색 단자를 같은 색 오른쪽 단자로 끌어 잇는다.
  5. **결재 도장 찍기**: 서류 3장에 도장을 찍는다. 빈칸 안에 찍어야 인정.
  6. **화분 물 주기**: 물뿌리개를 기울여 물 게이지를 초록 칸에 맞춘다.
- 직원 한 명당 임무 5개를 받는다. 장소가 겹치지 않게 뽑는다.
- 화면 위에 **전체 임무 진행 바**가 있다. 산 직원과 유령 직원의 임무가 모두 반영된다.
- 임포스터는 가짜 임무 목록을 받는다. 장소에 가서 사용해도 진행 바는 안 오른다.
- 미니게임 중에도 몸은 그 자리에 있다(킬당할 수 있다). 창을 닫으면 처음부터.

### 시야
- 직원 시야 반경 6칸, 임포스터 9칸.
- 벽에 가려진 곳은 어둡다. 내 위치에서 벽 꼭짓점으로 광선을 쏴서 보이는 다각형을 만든다.
- 어두운 곳의 다른 플레이어와 시체는 그리지 않는다.

### 킬
- 임포스터가 1.5칸 안의 산 직원에게 Q.
- 쿨다운 25초. 게임 시작과 회의 직후에도 25초부터 시작한다.
- 맞은 직원은 그 자리에 시체를 남기고 유령이 된다. 임포스터는 시체 위치로 순간이동한다.

### 신고와 긴급 회의
- 시체 1.5칸 안에서 R → 회의.
- 회의실 긴급 버튼 → 회의. 한 사람당 한 판에 1번. 게임 시작·회의 끝나고 15초 동안은 못 누른다.
- 사보타주(서버 과열)가 진행 중이면 긴급 버튼은 막힌다.

### 회의
1. 신고·버튼을 누르면 모든 플레이어가 회의 화면으로 넘어간다. 게임 화면의 시체는 전부 치운다.
2. **토론 60초**: 왼쪽에 플레이어 카드(색, 이름, 죽음 표시, 신고한 사람 표시), 오른쪽에 채팅창.
3. **투표 30초**: 카드를 눌러 투표하거나 "건너뛰기". 한 번 고르면 못 바꾼다. 다 투표하면 바로 끝난다.
4. 결과: 가장 많은 표를 받은 사람이 추방된다. 동점이거나 건너뛰기가 가장 많으면 아무도 추방되지 않는다.
5. 추방 연출 4초: "OOO 님은 임포스터였습니다" 또는 "OOO 님은 임포스터가 아니었습니다". 남은 임포스터 수도 보여 준다.
6. 모두 회의실 탁자 둘레에서 다시 시작.

- 유령은 회의 화면을 보지만 투표하지 못한다.
- 채팅 글자는 최대 120자. 유령 채팅은 유령에게만 보인다.
- 토론과 투표 시간은 첫 버전에서 고정값이다.

### 환풍구 (임포스터만)
- 환풍구 3쌍: A1↔A2, B1↔B2, C1↔C2.
- 환풍구 위에서 E → 들어간다(남에게 안 보인다). 안에서 E → 짝 환풍구로 이동. 방향키 → 나온다.
- 들어가고 나올 때 다른 사람이 시야 안에 있으면 그 사람에게는 보인다.

### 사보타주 (임포스터만, Tab 메뉴)
- 사보타주 쿨다운 30초. 하나가 진행 중이면 다른 것을 못 건다.
- **정전**: 직원 시야가 1.5칸으로 줄어든다(임포스터는 그대로). 창고 두꺼비집에서 직원 한 명이 사용하면 복구.
- **서버 과열**: 화면에 45초 카운트다운. 서버실 패널 1과 렌더팜 패널 2를 **두 직원이 동시에** 누르고 있어야 복구. 시간이 다 되면 임포스터 승리.

### 유령
- 벽을 통과한다. 시야 제한이 없다.
- 직원 유령은 남은 임무를 계속할 수 있다. 진행 바에 반영된다.
- 임포스터 유령(추방된 임포스터)은 사보타주만 걸 수 있다. 킬은 못 한다.
- 산 사람에게 유령은 안 보인다. 유령끼리는 반투명하게 보인다.
- 신고, 긴급 버튼, 투표는 못 한다.

### 승리 조건
- **직원 승리**: 전체 임무 진행 바가 다 찬다. 또는 임포스터가 전부 추방된다.
- **임포스터 승리**: 산 임포스터 수 ≥ 산 직원 수. 또는 서버 과열 시간 초과.
- 판이 끝나면 결과 화면(누가 임포스터였는지) 10초 뒤 대기실로 돌아간다. 같은 방 코드로 다시 할 수 있다.

### 나간 사람
- 대기실에서 나가면 그냥 빠진다.
- 게임 중 나간 사람(5초 동안 `seen`이 안 늘어난 사람)은 죽은 것으로 치고 시체는 남기지 않는다. 승리 조건을 다시 계산한다.
- **방장이 나가면 판이 끝난다.** "방장이 나갔습니다" 안내 후 남은 사람 중 입장이 가장 빠른 사람이 새 방장이 되어 대기실로 돌아간다.
  - 이유: 역할은 방장만 전부 안다. 방장을 넘기면 다른 사람에게 역할을 넘겨야 해서 비밀이 깨진다. 첫 버전에선 판을 끝내는 게 단순하고 안전하다.

### Firebase 데이터 (`crew/<방코드>/`)

| 경로 | 누가 쓰나 | 내용 |
|---|---|---|
| `meta` | 방장 | `host`(pid), `phase`(lobby·play·meeting·result), `imp`(1·2), `born` |
| `who/<pid>` | 본인 | `name`(≤12자), `color`(0~9), `join`, `seen`, `pub`(ECDH 공개키) |
| `in/<pid>` | 본인 | `x`,`y`(-1~1 이동 입력), `n`(명령 번호), `k`(명령 종류), `a`(명령 인자) |
| `chat/<시각_pid>` | 본인 | `p`(pid), `m`(≤120자), `t`, `g`(유령 채팅 여부) |
| `sec/<pid>` | 방장 | 그 사람만 풀 수 있는 역할·임무 목록 (`iv`, `ct`) |
| `st` | 방장 | 10Hz 상태 꾸러미 |

- **명령 칸**: `n`이 바뀔 때마다 방장이 한 번 처리한다. 종류(`k`): `use`(임무 완료·버튼·환풍구·패널), `kill`, `report`, `vote`, `sab`, `color`. 인자(`a`)는 대상 pid나 장소 id.
- 방장은 명령을 그대로 믿지 않고 검증한다: 킬 거리·쿨다운·역할, 임무 장소와의 거리, 투표 시간대 등.
- 미니게임 성공 자체는 검증할 수 없다(브라우저 안에서 일어난다). 장소 근처에 있는지만 확인한다.

### Firebase 규칙 (`docs/firebase-rules-crew.json`)

기존 `scores`, `rooms` 블록은 그대로 두고 `crew` 블록만 추가한다. 사용자가 Firebase 콘솔에서 붙여넣고 게시한다(Claude는 콘솔에 접근하지 않는다). 붙이기 전에 현재 게시된 규칙을 백업한다.

```json
"crew": {
  "$code": {
    ".read": "$code.length == 4",
    ".write": "$code.length == 4",
    "meta": {
      ".validate": "newData.hasChildren(['host','phase'])",
      "host":  { ".validate": "newData.isString() && newData.val().length <= 24" },
      "phase": { ".validate": "newData.isString() && (newData.val() == 'lobby' || newData.val() == 'play' || newData.val() == 'meeting' || newData.val() == 'result')" },
      "imp":   { ".validate": "newData.isNumber() && newData.val() >= 1 && newData.val() <= 2" },
      "born":  { ".validate": "newData.isNumber()" },
      "$other": { ".validate": false }
    },
    "who": {
      "$pid": {
        "name":  { ".validate": "newData.isString() && newData.val().length <= 12" },
        "color": { ".validate": "newData.isNumber() && newData.val() >= 0 && newData.val() <= 9" },
        "join":  { ".validate": "newData.isNumber()" },
        "seen":  { ".validate": "newData.isNumber()" },
        "pub":   { ".validate": "newData.isString() && newData.val().length <= 200" },
        "$other": { ".validate": false }
      }
    },
    "in": {
      "$pid": {
        "x": { ".validate": "newData.isNumber() && newData.val() >= -1 && newData.val() <= 1" },
        "y": { ".validate": "newData.isNumber() && newData.val() >= -1 && newData.val() <= 1" },
        "n": { ".validate": "newData.isNumber()" },
        "k": { ".validate": "newData.isString() && newData.val().length <= 10" },
        "a": { ".validate": "newData.isString() && newData.val().length <= 24" },
        "$other": { ".validate": false }
      }
    },
    "chat": {
      "$id": {
        ".validate": "newData.hasChildren(['p','m','t'])",
        "p": { ".validate": "newData.isString() && newData.val().length <= 24" },
        "m": { ".validate": "newData.isString() && newData.val().length <= 120" },
        "t": { ".validate": "newData.isNumber()" },
        "g": { ".validate": "newData.isBoolean()" },
        "$other": { ".validate": false }
      }
    },
    "sec": {
      "$pid": {
        "iv": { ".validate": "newData.isString() && newData.val().length <= 32" },
        "ct": { ".validate": "newData.isString() && newData.val().length <= 600" },
        "$other": { ".validate": false }
      }
    },
    "st": { ".validate": "newData.hasChild('t')" },
    "$other": { ".validate": false }
  }
}
```

## 비밀 지키기

- **역할**: 각 브라우저가 입장할 때 ECDH 키 쌍을 만들고 공개키만 `who/<pid>/pub`에 올린다. 방장은 각 사람의 공개키로 나눠 가진 비밀키를 만들어 역할·임무 목록을 AES-GCM으로 잠가 `sec/<pid>`에 올린다. 본인만 풀 수 있다. 개발자 도구로 `sec`를 봐도 남의 역할은 못 읽는다.
- **상태 꾸러미(`st`)에는 역할을 싣지 않는다.** 임포스터끼리는 서로 알아야 하므로, 임포스터의 `sec`에 동료 임포스터 목록을 같이 넣는다.
- **감수하는 것 (사내 게임이라 허용)**:
  - 방장은 모든 역할을 안다. 개발자 도구로 볼 수 있다.
  - `st`에 모든 사람의 위치가 실리므로 개발자 도구로 어둠 속 위치를 볼 수 있다.
  - 유령 채팅도 Firebase에는 다 있으므로 개발자 도구로 볼 수 있다.
  - 환풍구 안에 있는 임포스터 위치도 `st`에 실린다.

## 화면

- **첫 화면**: 이름 입력, "방 만들기", "방 코드로 들어가기".
- **대기실**: 방 코드 크게 + 복사 버튼, 참가자 목록(색 점 + 이름), 색 고르기, 방장만 임포스터 수와 "시작" 버튼. 4명 미만이면 시작 버튼이 꺼져 있고 이유를 글로 보여 준다.
- **게임 화면**: 위에 임무 진행 바, 왼쪽에 내 임무 목록, 오른쪽 아래에 사용·킬·신고·사보타주 버튼(쿨다운이 원으로 줄어든다). 내 역할은 시작할 때 3초 큰 글씨로 알려 주고, 이후 왼쪽 위에 작게 남긴다.
- **연결 상태**는 오른쪽 위에 색 점과 한글 문장으로 항상 보인다(초록 "연결됨", 노랑 "다시 연결 중", 빨강 "끊김").
- 오류는 한국어 안내 문장으로 보여 준다(예: "그런 방 코드가 없어요. 대문자와 숫자 4자리인지 확인하세요").

## 시험

- `node --test`로 순수 부분을 검증한다.
  - `rules.js`: 킬 거리·쿨다운, 신고 거리, 긴급 버튼 횟수·대기 시간, 투표 집계(동점, 건너뛰기, 전원 투표 시 조기 종료), 승리 조건 4가지, 정전 복구, 서버 과열 동시 누르기와 시간 초과, 환풍구 이동, 유령 제한, 나간 사람 처리.
  - `roles.js`: 임포스터 수, 임무 장소 중복 없음, 암호화 왕복(Node의 WebCrypto 사용), 남의 키로는 못 푸는지.
  - `snap.js`: 묶고 풀었을 때 같은 값.
  - `map.js`: 모든 임무 장소·환풍구·버튼·패널에 시작 위치에서 걸어서 닿을 수 있는지(격자 채우기).
  - **한 판 통째로**: 가짜 플레이어 6명을 `rules.js`에 물려 임무 하기, 킬, 신고, 투표까지 자동으로 끝까지 돌리고 승리 판정이 나는지 본다.
- 브라우저 확인: 로컬 서버를 띄우고 탭 2~4개로 실제 Firebase에 접속해 대기실 → 게임 → 회의 → 결과까지 한 바퀴 돈다. 스크린샷으로 보여 준다.
- 숨은 탭에서는 rAF가 안 돈다(모코파크에서 확인된 함정). 긴 플레이 검증은 Node로 하고, 브라우저는 화면 확인용으로만 쓴다.

## 만드는 순서

1단계에서 바로 한 판 해 볼 수 있게 만들고, 2단계에서 나머지를 붙인다.

1. **1단계**: 대기실, 이동, 충돌, 시야, 임무 6종, 킬, 신고, 긴급 회의, 채팅, 투표, 추방, 승리 조건, 역할 암호화.
2. **2단계**: 환풍구, 사보타주 2종, 유령(벽 통과, 유령 임무, 유령 채팅).
